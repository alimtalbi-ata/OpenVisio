# OpenVisio V43.24 — cumulative ZIP / Git blob parity

Author: Abdelhalim Talbi. This gate is part of the Windows candidate pipeline; it does not certify compatibility with Microsoft Visio Desktop.

## Failure mode identified

The V43.24 cumulative ZIP's own SHA-256 manifest and the mirrored source trees can be internally consistent while a packaged support file differs from the Git commit. The pre-gate byte comparison of the existing V43.24 candidate found CRLF payloads for .gitattributes and 02-Compilation/installer/OpenVisio-V43.24-Candidate.iss, while the Git tree recorded different blob IDs. The checked engine modules (model.py, vsdx.py, render.py, routing.py and related VSDX files) matched the Git blobs checked in that review; this was not evidence of engine source loss in that candidate.

## Enforced controls

1. .gitattributes now enforces LF for .iss and for itself, in addition to Python, JSON, YAML, Markdown, SVG and TXT.
2. verify_release_git_parity.py reads the exact HEAD blob map using one NUL-delimited git ls-tree call. It hashes each packaged engine/test module using Git's blob-object algorithm, checks expected path sets and mirror bytes, requires critical engine dependencies, pins release/build inputs, validates the manifest author/version and binds source_commit to the current checkout.
3. The Windows workflow runs this gate immediately after the cumulative ZIP is built and before the packaged test suite. A mismatch fails the job; the JSON report is uploaded as a separate CI artifact.
4. The independent-checkout PowerShell script pins the new verifier, both mirrored regression tests, .gitattributes and the modified workflow by Git blob ID.

## Scope and limits

This gate checks the complete tracked source and test trees shipped in the two mirrors plus the explicitly named release-critical inputs. The existing cumulative archive validator separately checks archive paths, manifest checksums, CRC and SHA-256. The gate does not prove every other tracked repository file is included, does not replace antivirus/signature validation of binaries, and does not test application behavior.

Microsoft Visio Desktop round-trip, manual Windows GUI acceptance and real application screenshots remain unperformed unless a later report explicitly records those tests.


## V43.24 route-attachment regression

The V43.24 engine adds an explicit attachment check for the first and last point of a preserved static VSDX orthogonal route. A source/target terminal must touch its corresponding device boundary within a two-unit rounding tolerance; otherwise the route validator rejects the record. Mirrored route tests include an attached route, detached source, detached target, rounding tolerance and document-level rejection. This verifies static-route metadata, not a full Visio Desktop rendering round-trip.
