**Author:** Abdelhalim Talbi

**Base source commit:** `fa4c799523098551df2de20f3d525e3465fa21e7`

## Functional change 1 — preserve static route waypoints

The external importer now recognizes a deliberately narrow public VSDX route subset: numeric, finite, bounded, formula-free endpoint and geometry cells; a MoveTo followed by LineTo rows; matching local-frame endpoints; and non-zero orthogonal segments. Coordinates are normalized from Visio page inches / Y-up into OpenVisio world pixels / Y-down.

Each imported edge may store a versioned `visio_route` record with the ordered points and source/target geometry signatures. The routing engine uses those points only while endpoint geometry still matches and no non-endpoint equipment rectangle intersects a segment. Changing either endpoint, adding an obstacle, or encountering an invalid record falls back to normal obstacle-avoiding route computation. Static routes are checked before shared-route memoization, so parallel SAN paths preserve their individual waypoints.

This is not a dynamic Visio glue engine. The importer does not evaluate arbitrary formulas, all local coordinate frames, dynamic master behaviour, or every connector representation.

## Functional change 2 — canonical identity of private payload entries

The existing V43.22 guard remains in the integrated tree: `openvisio/document.json` and `openvisio/manifest.json` are reserved private part names whose case must be canonical. A case alias is rejected rather than silently entering a fallback path that could lose editor-only metadata, layers or topology.

## Regression evidence

The route feature originates from the dedicated V43.22 static-waypoint branch and includes synthetic public OPC fixtures. Tests exercise preservation on re-import, independent parallel routes, orthogonality and rejection of malformed route schemas; obstacle or endpoint movement invalidates a preserved route.

This baseline predates integration of these static-route changes.
