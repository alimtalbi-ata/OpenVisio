# OpenVisio V43.23 — static VSDX waypoint preservation

Author: Abdelhalim Talbi · Candidate branch: `develop/v43.23-static-vsdx-routes-and-canonical-payload-20261026`.

## Problem

The source-free external VSDX importer previously preserved the orthogonal routing preference but rebuilt bend geometry. This discarded visible, static connector waypoints even when they were emitted in a public shape representation that OpenVisio could safely interpret.

## Functional change

The importer now extracts only a constrained public geometry subset: endpoint cells and all `MoveTo`/`LineTo` coordinates must be numeric, finite, bounded and formula-free; the first and last local points must match the connector frame; every non-zero segment must be axis-aligned. Those points are converted from page inches (Visio Y-up) to world pixels (OpenVisio Y-down).

Every edge stores `visio_route` schema 1, ordered source/target geometry signatures and a bounded point list. The normal validation contract rejects unknown schemas/keys, invalid dimensions, non-finite or out-of-range coordinates, duplicate adjacent points, diagonal segments and excessive point counts.

The routing scene uses these points only if both endpoint signatures still match and no non-endpoint equipment rectangle intersects a segment. A moved/resized endpoint, malformed record or new obstacle disables preservation and invokes the ordinary obstacle-avoiding router. Static route points are checked before the shared-route cache so parallel SAN links retain independent waypoints.

## Evidence boundary

The automated tests use source-free VSDX packages produced from OpenVisio fixtures, not Microsoft Visio Desktop documents. They cover import, two distinct parallel paths, public export/import, endpoint-edit invalidation, obstacle invalidation and malformed-route rejection. These tests do **not** certify real Visio interoperability. Arbitrary Visio formulas, dynamic glue, style/master fidelity and unsupported coordinate frames remain out of scope.
