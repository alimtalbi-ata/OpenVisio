# OpenVisio V43.27 — explicit ShapeSheet unit literals

**Author: Abdelhalim Talbi**

## Change

The bounded ShapeSheet scalar evaluator now recognizes a conservative set of universal units when they occur immediately after a numeric literal. Length units normalize to inches (OpenVisio's VSDX geometry coordinate unit); angular units normalize to radians. Supported suffixes include common forms of `in`, `ft`, `cm`, `mm`, `m`, `km`, `mi`, `yd`, `pt`, `deg` and `rad`, together with common singular/plural spellings and a trailing dot. For example, `GUARD(12 in)` becomes 12 inches, `120 mm` becomes 120/25.4 inches, and `90 deg` becomes π/2 radians.

## Safety boundaries

- Units bind only to a numeric token. Unknown, unattached and compound unit expressions remain unsupported and are refused.
- Existing token-count, formula-length, nesting, finite-result and magnitude limits remain enforced. No `eval`, imports or execution of formula code are introduced.
- The evaluator does not implement the full ShapeSheet language and does not perform dimensional type-checking between length and angle expressions. Unsupported formulas continue to be reported by the importer; strict fidelity still fails closed.
- Integration coverage uses synthetic VSDX packages. Microsoft Visio Desktop round-trip fidelity is **NOT TESTED**.

## Qualification status

The branch-local tests can validate the bounded evaluator and synthetic importer contract. Windows CI and the full suite must be reported only against the exact updated branch commit; no new binary is considered qualified until that workflow succeeds.
