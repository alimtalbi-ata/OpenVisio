# OpenVisio V43.21 - canonical VSDX ZIP paths

**Author:** Abdelhalim Talbi  
**Candidate branch:** develop/v43.21-canonical-archive-paths-20261025  
**Internal application version:** 42.50.0

## Priority change

The current source candidate treats VSDX as an untrusted Open Packaging Convention (OPC) ZIP. Before parsing embedded JSON or Visio XML, both mirrored importer files, 03-Sources/openvisio/vsdx.py and python/openvisio/vsdx.py, now require every raw member path to be canonical and unique after case folding.

Rejected spellings include absolute paths, backslashes, NUL/control characters, empty path segments, dot and parent segments, colon syntax, Windows-reserved DOS device names (including COM/LPT superscript variants), Win32 metacharacters, trailing dots/spaces, case-insensitive aliases, and file/directory name collisions. Compression-amplification and per-member size limits remain in force. This is a file-format robustness change; it does not imply Microsoft Visio compatibility certification.

The cumulative-release validator checks every ZIP member, including directory entries, before reading payloads. It rejects raw-path normalization aliases, case-fold collisions, Windows device names and file/directory paths that map to one Win32 target.

The package applies LF checkout rules to Python/config/document source files. CI extracts the completed cumulative ZIP to a clean temporary directory and reruns source/test parity plus the full bundled Python test suite. This catches missing test fixtures that are available in GitHub's full repository but were absent from an earlier ZIP candidate.

## Source of truth and V43.4 reconciliation

The local V43.4 archive is not a safe replacement for the current engine. Its manifest identifies an older partial candidate, references a checksum filename that is absent, does not contain the Python source/test mirrors, and omits routing.py and parallel_geometry.py. The archived model.py, vsdx.py, render.py and app.py Git-blob identities differ from the published source. The release workflow therefore packages the verified GitHub checkout and its real build outputs; it does not re-label the historical ZIP as current.

## Qualification gates

The candidate workflow is designed to verify an independent branch checkout, pin important Git blobs, check exact source/test mirror parity, run the Python suite, build the Windows x64 portable executable and Inno Setup installer, run automated smoke tests, render the PDF release brief to PNG pages, and validate the final cumulative ZIP (CRC, duplicate paths, version, source mirrors and SHA-256 coverage).

| Evidence | What it demonstrates | What it does not demonstrate |
|---|---|---|
| Unit/regression tests | Model, importer, renderer and guard behavior against synthetic fixtures | Full Microsoft Visio fidelity |
| GitHub Actions Windows build | Actual runner compilation and automated launch/I/O smoke | Manual end-user acceptance |
| Cumulative ZIP audit | Package completeness, path safety and cryptographic file integrity | Runtime correctness beyond recorded tests |
| Microsoft Visio Desktop | Not tested in this candidate | No import/export round-trip claim |
| Application screenshots | Not available for this run | PDF page previews are not application screenshots |

## Reproducibility

The final package records the exact source commit, source/test mirror contents, build/test logs, Windows executable hashes, per-file SHA-256 manifest, cumulative ZIP SHA-256 sidecar, Word/PDF report and PDF-render QA data. The main branch is not changed and no merge is performed automatically.
