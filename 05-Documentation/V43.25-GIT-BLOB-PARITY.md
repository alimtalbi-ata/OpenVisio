# OpenVisio V43.25 — cumulative ZIP / Git blob parity

**Auteur : Abdelhalim Talbi.** Le vérificateur de parité est une barrière de livraison; il ne certifie pas Microsoft Visio Desktop.

## Origine du contrôle

L'audit historique consigné dans la PR #54 et le contrôle V43.23 ont montré qu'une archive peut posséder un manifeste SHA-256 interne cohérent et des miroirs de code identiques, tout en embarquant un fichier de support dont les octets ne correspondent pas au blob Git. Le contrôle V43.23 avait notamment identifié un problème de normalisation de fins de lignes pour `.gitattributes` et le script Inno Setup. Ce constat historique concerne le candidat V43.23; **aucun résultat d'audit d'une archive V43.25 n'est présumé ici**.

## Contrôles présents dans le candidat V43.25

1. `.gitattributes` fixe les fins de ligne LF pour `.iss` et pour lui-même, en plus des sources Python, JSON, YAML, Markdown, SVG et TXT.
2. `verify_release_git_parity.py` calcule les identifiants Git-blob des octets inclus dans le ZIP et les compare au tree du checkout sélectionné. Il vérifie les chemins attendus, les deux miroirs moteur/tests, les modules critiques, les entrées de build et le `source_commit` du manifeste.
3. Le workflow Windows appelle ce contrôle après la création du ZIP cumulatif et avant la suite de tests depuis l'extraction propre; une divergence doit faire échouer la qualification. Le rapport JSON est prévu comme artefact distinct.
4. Le contrôle PowerShell de checkout indépendant épingle les blobs du moteur, les tests, le script de parité, les outils de build, le workflow et les documents critiques.

## Ce que ce contrôle ne prouve pas

Le contrôle de blobs ne remplace ni l'audit structurel et SHA-256 de l'archive, ni l'analyse des dépendances/exécutables, ni les tests fonctionnels. Il ne prouve pas que tous les autres fichiers du dépôt non listés comme entrée critique sont livrés; le contrôle de périmètre des arbres source et tests reste distinct.

Les tests VSDX utilisent des fixtures synthétiques. Le round-trip Microsoft Visio Desktop, la recette interactive Windows manuelle et les captures réelles de l'application restent non effectués tant qu'un rapport ultérieur ne fournit pas une preuve explicite.

## Régression V43.25 — filtre spatial des routes statiques

V43.25 interroge le même index conservatif de rectangles que le routeur pour réduire les obstacles candidats à ceux dont les limites rembourrées peuvent recouper l'enveloppe complète d'une route VSDX préservée. Le contrôle exact des signatures d'extrémités, des segments et des obstacles reste inchangé. Si les métadonnées de route sont malformées, le chemin complet est conservé; le filtre n'autorise jamais l'acceptation d'une route.

Trois régressions déterministes vérifient : 1 200 équipements éloignés sans changer la géométrie, un obstacle intersectant qui ne doit pas être filtré, et une route non finie qui doit revenir au balayage complet. Le workflow Windows épingle les blobs du moteur et des tests, construit le candidat cumulatif et rejoue la suite depuis une extraction propre.

**Limite :** ces fixtures sont synthétiques. Aucun aller-retour Microsoft Visio Desktop, aucune recette interactive Windows et aucune capture réelle de l'application ne sont revendiqués.
